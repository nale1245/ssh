### 需要说明的 4 个数据问题

1. **500+ 为什么用 1000 而不是 501**：2021-2024 名次一直排到 594 名，第 501 名是**真实存在的名次**（7 条）。
   若把 500+ 映射成 501 会与真实第 501 名混淆，因此改用远大于真实名次的哨兵值 `1000`。
   前端展示时把 `rank >= 1000` 渲染成「500+」即可。
2. **软科会给同一学校换 slug**：如常熟理工学院 2021-2022 用 `...-2`、2023-2024 用 `...-3`、2025-2026 用原名 slug。
   清洗时按「同名同省」合并，规范 slug 取覆盖年份最新的一个（`changshu-institute-of-technology`），学校数 603 → 600。
3. **校名/省份变更取最新年份**：天水师范学院→天水师范大学、常熟理工→苏州工学院、西藏农牧学院→西藏农牧大学；
   河北工业大学在软科数据中省份由「天津」变为「河北」，按最新年份取「河北」。
4. **分项得分只有前 100 名**：`score_research/talent/social` 大量为 NULL 属数据源特性，不影响 P0。

## 4. 建表结果（MySQL 5.7.28）

数据库：`university`，字符集 `utf8mb4 / utf8mb4_unicode_ci`。

| 表 | 行数 | 说明 |
|---|---|---|
| university | **600** | 学校主表，`name` 唯一 |
| ranking | **3535** | 历年排名，`(univ_id, year)` 唯一 + 外键 |
| admission | 0 | 阶段 5 招生爬虫写入，先建空表 |

约束：
- `ranking.uk_univ_year (univ_id, year)`：一校一年一条
- `ranking.idx_year_rank (year, rank)`：按年查询/排序
- 三张子表均对 `university(id)` 建外键（ON DELETE RESTRICT / ON UPDATE CASCADE）
- `university.idx_province`：地图按省聚合

`SHOW CREATE TABLE ranking` 已确认 `rank INT DEFAULT NULL COMMENT '...500+ 记为 1000...'`、
`score_* DECIMAL(6,2)`、`stars TINYINT`、外键与唯一键均生效。

## 6. 已知限制

1. **数据结构与文档差异**：设计文档 v2 `3.1 的 `university.city` 按用户要求取消；其余字段与文档一致。
2. **rank 哨兵值 1000**：阶段 3 的接口按原值输出，前端展示层把 `>= 1000` 显示为「500+」；
   不要把它当成真实名次参与均值/分位数计算。
3. **MySQL 版本 5.7**（本机只有 5.7.28，文档写 8.x）：建表语句已按 5.7 验证，无 8.0 特性依赖。
4. **`stars` 是派生字段**：软科主榜不发布星级，按名次分段映射，报告中需说明口径。
